# Quote and Billing Build Spec

Oct 2, 2026 · William. Transcribed from the PDF on 2026-10-06. The **Amendments** section
at the end records every decision made since, and wins over the body where they differ.

## Summary

Build a "Quote and billing" screen in the Projects PWA that replaces typing quotes and
invoices in Xero's UI. Xero stays the ledger: the app creates approved invoices in Xero
through the existing API connection, and the quote itself is never created in Xero.

The screen has three parts:

1. A quote line editor with insert-anywhere rows, optional section titles, optional units
   and an optional discount.
2. Price memory that suggests past quoted prices as William types, filtered by property
   type.
3. A payment schedule (deposit, progress payments, final) where each stage is billed to
   Xero with one click.

The clickable mock-up William approved is `docs/quote-billing-mockup/quote-billing-mockup.html`.
It uses sample data only. Treat it as the reference for layout and behaviour; where this
spec and the mock-up differ, this spec wins.

## Quote line editor

The editor is a table of rows in a fixed order. A row is either an item or a title.

**Item row columns:** line number, description, service, quantity, unit (optional), unit
price, amount, row actions.

- Service is a dropdown (see Amendments: the source is the `Categories` tab).
- Amount = quantity × unit price, rounded to 2 decimals.
- Line numbers count item rows only. Title rows are not numbered.

**Row actions on every item row:**

- "+ Above" and "+ Below" insert a blank item row at that position and put the cursor in
  its description.
- "+ Title" inserts a title row above this row.
- Duplicate, move up, move down, delete.
- Pressing Enter in a description inserts a blank item row directly below.
- A new row copies the service of the nearest item row.
- "+ Add line at the end" and "+ Add title at the end" sit under the table.

**Title rows:**

- One text field, shown in capitals, with no quantity or price.
- Shows the subtotal of the item rows under it, up to the next title row.
- Has "+ Above", "+ Below", move up, move down and delete. Deleting a title leaves its
  item rows in place.
- Moving a title moves only the title row.

**Units:**

- The unit box is hidden by default. A "Show unit" tick box above the table shows it next
  to quantity on every item row.
- It switches on automatically when a picked suggestion is priced per sqft or ft run.
- Options: no unit, pcs, sqft, ft run, lot, room, lumpsum.

**Discount and totals:**

- Totals show Subtotal, then "+ Add discount". Nothing else shows until it is pressed.
- A discount is one value for the whole quote, entered as $ or %, and can be removed.
- Contract sum = subtotal minus discount. Show "No GST" under it.
- "Save quote" saves the lines and writes the item rows to price history (see Data
  model).

**Layout:** desktop first. On a phone the table scrolls sideways inside its own container;
the page itself must not scroll sideways.

## Property type and price memory

Every quote has a property type (HDB, Condo or Commercial), and price suggestions only
ever fill a price from a past quote of the same type.

**Property type:** three buttons at the top of the screen. The value is saved on the quote
and on every price history row written from it.

**Suggestions while typing:**

- Trigger when the description of the focused item row has 3 or more characters.
- Version 1 matching: split the typed text into words of 2 or more characters; a past item
  matches when its description contains every word, ignoring case. Show at most 4
  matches.
- Show the matches in a panel directly under the row (not a floating dropdown).
- Each match shows: description, service and unit, every past quote (property type, price,
  month, client), and the last price for the current property type.
- Picking a match fills description, service and unit. It fills the unit price only if a
  past quote exists for the current property type. If none exists, leave the price blank.
- "None of these. Keep what I typed." closes the panel for that row.
- Suggest only. Never change a price William has already typed.

**Price check under a row:** when a row's description exactly matches a past item, show
one line under it:

- Price blank: the last quote for this property type (price, month, client).
- Price entered: how much higher or lower it is than that last quote, or that it is the
  same.
- No past quote for this property type: say so and list the other types' last prices for
  reference.

**One-time import:** before launch, pull the line items of all past Xero sales invoices
through the API into the price history tab: description, unit price, quantity, invoice
date, contact and service tracking option. Past invoices have no property type, so import
them with property type blank. Blank-type rows show in suggestions for reference but never
fill a price.

**Later, not version 1:** smarter matching for descriptions worded differently, if keyword
matching misses too much.

## Payment schedule and stage billing

Each quote has a payment schedule set once, and each stage is billed with one "Bill now"
click that creates a one-line approved invoice in Xero.

**Schedule card (under the line table):**

- Rows: stage name (editable), share in %, amount, status, remove.
- A new quote starts with Deposit and Progress payment 1 to 3, with the shares left blank
  for William to fill in. The shares in the mock-up are examples only.
- "+ Add stage" adds a row; remove deletes one. No fixed limit.
- The last row is always "Final payment (balance)". Its share is 100% minus the other
  stages and cannot be edited.
- Stage amount = contract sum × share, rounded to 2 decimals.
- If the shares add up to more than 100%, show a warning and disable "Bill now" until
  fixed.

**Billing a stage:**

1. William presses "Bill now" on a stage. The next unbilled stage is highlighted, but any
   unbilled stage can be billed.
2. The app shows the invoice number, client and amount to confirm, then creates an
   approved invoice in Xero with one line, e.g. "Progress payment 1, 20% of contract sum
   $1,014.00".
3. The stage row changes to "Billed" and stores the Xero invoice ID, the amount and the
   date.
4. The invoice is approved on creation, so it appears on the client's statement of
   account straight away.

**Rules that protect the numbers:**

- Once a stage is billed, its amount is fixed at what was invoiced. Its share and name
  become read-only.
- If the quote changes after a stage is billed, unbilled stages recalculate from the new
  contract sum.
- Final payment amount = contract sum minus the invoiced amounts of all billed stages,
  minus the amounts of any stages still unbilled. Calculating it this way absorbs rounding
  differences.
- A billed stage can only be removed after its Xero invoice is voided. Version 1 can
  simply block removal and show a message.

## Variation orders

A variation order (VO) is a separate set of lines for extra work, billed in full as its
own invoice and kept out of the stage amounts.

- "+ Variation order" on the schedule card opens the same line editor, blank, with the
  project's property type.
- VOs are numbered per project: VO1, VO2 and so on.
- "Bill now" on a VO creates an approved Xero invoice containing all of the VO's lines,
  including title rows, units and any discount.
- VO item rows are written to price history like quote rows.
- The project screen lists the quote stages and the VOs together with their billed
  status, so William can see everything billed and unbilled for the project.

The mock-up only shows a note for this button; the VO editor itself is not mocked up.

## Xero integration

The app only creates sales invoices (type ACCREC) and never creates Xero quotes.

| Action in the app | What is sent to Xero |
|---|---|
| Bill a stage | One approved invoice with one line: stage name, share and contract sum in the description, quantity 1, unit amount = stage amount |
| Bill a variation order | One approved invoice with one line per item row, plus description-only lines for title rows |
| Save quote | Nothing |
| First stage billed (deposit) | Attach the quote PDF to that invoice through the Attachments API |

**Invoice fields:**

- Contact: the project's client from the Contacts tab, matched to the Xero contact.
- Status: AUTHORISED (approved), so the invoice appears on the contact's statement.
- Invoice number: generated by the app (see Invoice numbering below).
- Reference: the project name only. The stage name or VO number goes in the line
  description.
- No GST on any line. Use the no-tax setting that matches the organisation's Xero tax
  setup.
- Tracking: set the "Service" tracking option on VO item lines from the row's service. For
  stage invoices, see open questions.
- Unit: Xero lines have no unit field, so append the unit to the description when one is
  set, e.g. "Gypsum board partition wall (per sqft)".
- Discount on a VO: send as a final negative line, "Less: discount".
- Title rows: send as a line with a description only, no quantity, amount or account.

**Invoice numbering:**

- Format: see Amendments (`INV-YYMMDD-XX`). The date is the invoice date in Singapore
  time.
- XX starts at 01 for the first invoice of that date and goes up by one for each further
  invoice with the same date.
- To find the next XX, check both the app's own records and Xero for numbers with that
  date prefix, so a number typed by hand in Xero is never reused.
- Xero rejects a duplicate sales invoice number. If that happens, take the next XX and
  retry once (see Amendments for the safe form of this rule).
- The number is shown on the confirm step before the invoice is created and is stored on
  the stage or VO row.

**Contact matching (statement of account):**

- Every invoice is created against the client's existing Xero contact using its Xero
  ContactID, stored on the Contacts tab.
- Never send a contact by name only. Xero creates a new contact when the name does not
  match exactly, and the invoice would land on the wrong statement.
- If the project's client has no Xero ContactID, block "Bill now" and ask William to link
  the client to a Xero contact first.
- Xero statements include approved invoices only, not drafts. This is why invoices are
  created as approved.

**Failure handling:** if the Xero call fails, do not mark the stage or VO as billed. Show
the error and let William retry. Store the Xero invoice ID on success so a retry cannot
create a duplicate.

**Quote PDF:** the app generates the quote PDF itself, with section titles, units, section
subtotals, discount, contract sum, "No GST" and the payment schedule.

## Data model

Four new tabs in the operations Google Sheet hold everything; column names are
suggestions and JY can rename them to fit the existing conventions.

| Tab | One row per | Columns |
|---|---|---|
| Quotes | Quote or variation order | quote_id, project_id, kind (quote / vo), vo_number, property_type, show_unit, discount_mode ($ / %), discount_value, subtotal, contract_sum, status, created_at, updated_at |
| Quote lines | Row in the editor | line_id, quote_id, position, kind (item / title), description, service, qty, unit, unit_price, amount |
| Payment stages | Stage of a quote | stage_id, quote_id, position, name, share_pct, is_final, billed_amount, billed_at, xero_invoice_id, xero_sync_status |
| Price history | Quoted item | history_id, description, service, unit, unit_price, qty, property_type, client, quoted_at, source (quote / vo / xero_import), quote_id or xero_invoice_id |

Notes:

- `position` is what makes insert-above and move up/down work. Rewrite positions for the
  whole quote on save.
- Price history is append-only. Saving a quote again must not duplicate its rows.
- A VO's billed state can live on the Quotes row (xero_invoice_id, billed_at) since it is
  billed in one invoice.
- Suggestions group price history rows by description (case-insensitive) to show the list
  of past quotes per item.

## Build order and acceptance checks

Build in five steps, each usable on its own.

1. **Price history import.** One-off script that fills the Price history tab from past
   Xero invoices. William can search the tab by hand straight away.
2. **Quote line editor.** Rows, insert controls, titles, units, discount, totals, save to
   Sheets, write to price history.
3. **Suggestions and price check.** Wired into the editor, filtered by property type.
4. **Payment schedule and "Bill now".** Stage invoices to Xero (approved; the PDF's word
   "drafts" here was a leftover, see Amendments).
5. **Variation orders and quote PDF.** VO editor and billing, PDF generation, PDF attached
   to the deposit invoice.

**Acceptance checks:**

- [ ] A row can be inserted above or below any row without dragging, and the cursor lands
      in the new row.
- [ ] A quote with no titles, no units and no discount shows none of those controls in use
      and saves cleanly.
- [ ] A title row shows the subtotal of the rows under it and is not numbered.
- [ ] Typing "13a socket" on an HDB quote suggests past socket items and fills the last HDB
      price only.
- [ ] On a property type with no past quote for the item, the price stays blank and other
      types' prices are shown.
- [ ] Picking an item priced per sqft or ft run switches the unit box on.
- [ ] Totals never show GST.
- [ ] "Bill now" on a stage creates exactly one approved invoice in Xero with one line and
      the correct amount, and the stage shows "Billed".
- [ ] Pressing "Bill now" twice, or retrying after an error, never creates two invoices for
      one stage.
- [ ] The billed stage amounts plus the final payment always equal the contract sum to the
      cent.
- [ ] A VO invoice in Xero matches the VO lines, including title rows as description-only
      lines.
- [ ] Two invoices billed on the same date get numbers ending -01 and -02, and a number
      already used in Xero for that date is skipped.
- [ ] Each invoice appears on the statement of account of the project's client in Xero, and
      no new contact is created.

## Open questions

Still open (see Amendments for the ones answered):

- [ ] Stage invoices are one line covering several trades. Which "Service" tracking option
      should they carry: General, none, or the quote's main trade?
- [ ] Should the client-facing quote PDF show section subtotals, or only the editor?
- [ ] Should past Xero invoices be imported with property type blank, or will William tag
      the common items by type after import?
- [ ] Are there other units in use beyond pcs, sqft, ft run, lot, room and lumpsum?

**Out of scope for this build:**

- Creating or syncing quotes in Xero.
- Discounts on individual lines.
- Calculating one property type's price from another.
- Moving a whole section together with its title.
- Client online acceptance of quotes. The client confirms by WhatsApp, email or signed PDF
  as now.
- Emailing invoices from the app. That stays in Xero.
- Tying labour hours into quote pricing. That belongs to the separate project costing
  view.

## Amendments

Decided between JY and Claude on 2026-10-05 and 2026-10-06, after reading the repo, the
sibling `expense-pwa`, the live workbook and live Xero (read-only). These override the
body above.

**Xero connection**
- This app has its own Xero app registration and its own token set, stored in `System
  config` as `XERO_PROJECTS_ACCESS_TOKEN` / `_REFRESH_TOKEN` / `_TOKEN_EXPIRY`. It never
  touches the expense app's `XERO_*` tokens (refresh tokens are single-use; two apps
  sharing one set lock each other out). Authorised on 2026-10-06 via
  `scripts/xero-auth.mjs`, with contacts and settings scopes read-only so the app cannot
  create a Xero contact.
- Invoices are created as **AUTHORISED** (Xero "Awaiting payment"). This is the first
  time the system posts straight to the ledger; the expense app only creates drafts. A
  mistake means void in Xero and re-bill.
- **Due date = invoice date + 14 days**, held in System config.
- **Invoice number format is `INV-YYMMDD-XX`** (two-digit year), the shape William already
  types by hand, e.g. `INV-261005-01`. The check against Xero before each number is what
  prevents a clash with hand-typed ones.
- Duplicate-number retry, safe form: the intended number is stored on the stage *before*
  the Xero call. On any retry or duplicate-number rejection, look that number up in Xero
  first; if it exists with this stage's contact, reference and amount, adopt it rather
  than sending again.
- Sales account code: every priced line on the sampled live sales invoices uses **200**,
  and every line is NoTax. 200 is the expected answer, to be confirmed by William and
  held in System config.

**Config lives in the workbook.** Account code, due days, units, property types and the
stage tracking option are `System config` keys, not code constants.

**Service list — one list for both apps.** The dropdown comes from the `Categories` tab.
A new `xero_tracking_option` column on `Categories` (column E) holds the Xero "Service"
option name per code and replaces the `CATEGORY_TO_TRACKING` map hard-coded in
`expense-pwa/lib/constants.js`; the expense app will be changed to read it. Known gaps
to fix in that column: `AIRC` is unmapped today (aircon bills go to Xero untagged);
`CEIL` is "Partition / Ceiling" in Xero; `OTHR` has no Xero option. `WRKR`, `TRANS` and
`VEHIC` stay in the list (William: don't worry about it).

**Contacts.** A `xero_contact_id` column is appended to `Contacts` (column H). Only one
of the 8 sheet contacts matches a Xero contact by exact name, so a one-time script
fetches the Xero list and proposes pairs for JY/William to confirm; it never auto-writes
a guess.

**Old invoicing tabs.** `Invoices`, `Payments` and `Payment allocations` (one 2025 sample
row each) are deleted in Phase 1 along with their `TAB_*` keys and `INVOICE_PREFIX`. Six
`Reports` formulas (rows 7–11, 26) read them and must be repointed or removed first.
Apps Script (unreadable via API) must be checked for the three names before deletion.

**Data layer.**
- IDs are never reused: line IDs are per-quote counters, e.g. `Q-0012-L7`.
- Saves are versioned: each save appends the lines as a new version, then flips one
  `current_version` cell on the quote. Older versions are pruned on each save, keeping
  the current one and any version that was current when something was billed.
- Every quote, VO and stage records `created_by` / `updated_by` / `billed_by` with
  timestamps (the name from the session; a label, not proof of identity).
- No checkbox columns in the new tabs; booleans are `TRUE`/`FALSE` text.

**Access.** Treat the app as admin-only (its users are). Billing routes should still
refuse unauthenticated calls server-side; PIN re-entry on the confirm step is the
proposed mechanism.

**Screen.**
- Needs its own wide layout (the mock-up table is 1,260px); the app's 720px `AppShell`
  column is untouched for other screens.
- Keep from the mock-up: the last remaining line cannot be deleted; a $ discount is
  capped at the subtotal and a % discount at 100; Enter in a title row adds an item
  line below it.
- A refresh button on the screen, since the service worker caches API reads.
- Look: mock-up layout and behaviour with the app's own fonts and colours from
  `lib/theme.js` (pending William's view).
