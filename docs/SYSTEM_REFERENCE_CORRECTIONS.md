# Corrections to SYSTEM_REFERENCE.md

Findings from building this app against the live workbook, 2026-08-08/09. Each was
verified by reading the sheet through the Sheets API, not inferred. Merge these into the
master `SYSTEM_REFERENCE.md` — they are kept separate here so the canonical doc is only
ever edited deliberately.

---

## 1. `Projects.client_id` runs the opposite way to the doc

**Doc says (§5.5):** `client_id` is typed, `client_name` is a VLOOKUP from Contacts.

**Actually:** column D (`client_name`) is the typed value. Column **C (`client_id`) is a
formula** deriving the ID *from* the name:

```
=IFERROR(INDEX(Contacts!A:A, MATCH(D42, Contacts!B:B, 0)), "")
```

It is also a **protected range named "autofilled"** and populates itself on any new row.
Writing to it is both unnecessary and blocked.

**Consequence:** any script creating a project must write `A:B` and `D:K` and leave C
alone. `client_name` must match `Contacts.company_name` exactly or the ID resolves blank.

## 2. Row insertion and deletion fail on the `Projects` tab

A row insert or delete is a structural change affecting every column, so it is rejected by
the protection on column C — even when writing only to A:B. `values.append` with
`insertDataOption: 'INSERT_ROWS'` fails; the default `OVERWRITE` works.

**Consequence:** rows in `Projects` cannot be deleted via the API at all. Clear `A:B` and
`D:K` instead, leaving C's formula.

## 3. Named ranges do not exist

**Doc says (§7):** five named ranges — `ActiveProjects`, `ClientContacts`,
`SupplierContacts`, `ActiveWorkers`, `ActiveCategories`.

**Actually:** the workbook has **zero** named ranges. Every consumer filters in code. The
existing `expense-pwa` already does this in `app/api/dropdowns/route.js`.

## 4. Note rows sit *inside* data ranges

Free-text `ℹ` guidance rows are not confined to the top:

| Tab | Note row |
|---|---|
| `Projects` | row 2 (data starts row 3) |
| `Expenses` | **row 4** — with data at row 2 and a blank row 3 |

**Consequence:** `.slice(1)` is wrong everywhere. Filter by ID prefix (`/^PRJ-/`,
`/^EXP-/`). This is a live bug in `expense-pwa`'s `app/api/history/route.js:26`, where two
junk rows currently appear in history for any admin user.

## 5. `Categories` schema and contents differ

- Column C is headed **`active_codes`**, not `is_active`. Values are the string `"TRUE"`.
- There is **no `MATL` (Materials) category**. The doc's §5.2 starter list is out of date.

Live list (14, all active): `PLMB TILE PAINT ELEC CARP DISP HACK GENL CEIL WRKR TRANS
CLEAN OTHR VEHIC`.

`lib/constants.js` in `expense-pwa` still maps `MATL` and `WTRP`, which no longer exist,
and is missing `CLEAN`.

## 6. Xero bill references do not carry the project code

**Doc says (§12):** `InvoiceNumber` is `{CategoryName} - {ProjectCode} - {ExpenseID}`,
e.g. `Tiling - PRJ-001 - EXP-001`.

**Actually**, live bill references read as `{receipt number} - {supplier}`:

```
2078461 - B&S Painting Materials
234435 - YJ Ceiling Materials
26105035473 - Choo chiang
113629 CSS - EXP-092-2143
```

No `PRJ-` code appears in any of them; only one carries an `EXP-` id.

**Consequence:** Xero has no project dimension at all — its only tracking category is
`Service` (trade). **Per-project spend cannot be derived from Xero**, only from the
`project_code` column in the `Expenses` tab.

## 7. Expense IDs are not max+1

**Doc says (§5.9):** "Uses max+1 logic — finds the highest existing EXP-NNN number and
increments by 1."

**Actually** `expense-pwa`'s `app/api/submit/route.js:33` uses a row count plus a
timestamp suffix:

```js
`EXP-${String(rowCount).padStart(3,'0')}-${Date.now().toString().slice(-4)}`
```

which is why live IDs look like `EXP-092-2143`. Row count is not deletion-safe, though the
timestamp suffix makes collisions unlikely in practice.

## 9. Workbook timezone was wrong

The workbook was set to **America/Los_Angeles** for a Singapore business, so every
`TODAY()` / `NOW()` was up to 15 hours out. **Changed to Asia/Singapore on 2026-08-08.**
Locale remains `en_US`, so scripts should write dates as ISO `YYYY-MM-DD`, which parses
unambiguously in any locale.

## New tab: `Project costs`

Added 2026-08-08. Non-receipted project costs — labour, transport, and materials bought
without a receipt. **Not linked to Xero.** Owned by the Projects PWA.

Header row 1, `ℹ` note row 2, data from row 3.

| Col | Field | Notes |
|---|---|---|
| A | `cost_id` | `PC-0001`, max+1, generated by the app |
| B | `created_at` | ISO 8601 with `+08:00`; stays text |
| C | `project_code` | FK → Projects |
| D | `display_address` | Snapshot at entry time |
| E | `cost_date` | Real date, `d mmm yyyy` |
| F | `cost_type` | `material` \| `labour` \| `transport` |
| G | `category_code` | FK → Categories |
| H | `category_name` | Plain-text snapshot, not a formula |
| I | `description` | Shown as the row's label in the app |
| J | `amount` | SGD |
| K | `invoiced` | Checkbox |
| L | `invoiced_date` | Stamped on tick, cleared on untick |
| M | `invoice_ref` | Reserved, unused |
| N | `created_by` | PWA user name |
| O | `updated_at` | ISO 8601 with `+08:00` |

**Gotcha:** the checkbox in column K reports `FALSE` on every formatted row, so the Sheets
`append` API believes the table runs to row 1000 and writes below it — outside the date and
currency formatting. Write by computing the row after the last `PC-` id instead.

**`GEN-000` rule:** browsable and can hold costs (general company expenses), but must be
excluded from every cross-project rollup or overheads inflate project figures.
